# Plan 03-01: Backend Socket.IO Presence, Typing Broadcaster & Read Receipts

**Phase:** 03 — Presence, Typing Indicators & Delivery/Read Status
**Plan:** 03-01 of 02
**Mode:** MVP vertical slice
**Estimated effort:** Medium (2–3 hours)

---

## Goal

Extend the Socket.IO server manager to track active user socket connections, record `lastSeen` timestamps on disconnect, broadcast transient typing start/stop events, and handle message status transitions (`SENT` -> `DELIVERED` -> `READ`) with real-time receipt event delivery to senders.

---

## Tasks

### Task 1 — User Connection Tracker & Presence Events

**File:** `server/src/sockets/socketManager.ts`

- Maintain `userSockets = new Map<string, Set<string>>()` mapping `userId` to active `socket.id`s.
- On connection:
  - Add `socket.id` to user's set.
  - If set size was 0 (first connection for this user), update `userSockets` and broadcast `user_presence` `{ userId, isOnline: true }` to all connected clients or personal rooms.
- On disconnect:
  - Remove `socket.id` from user's set.
  - If set is now empty (user has no active connections):
    - Update `User.lastSeen = new Date()` in database.
    - Broadcast `user_presence` `{ userId, isOnline: false, lastSeen: new Date().toISOString() }`.

---

### Task 2 — Presence REST Endpoint

**File:** `server/src/controllers/userController.ts` & `server/src/routes/userRoutes.ts`

- Add endpoint `POST /api/users/presence` (Body: `{ userIds: string[] }`) or `GET /api/users/presence?ids=id1,id2`
- Returns array of user statuses: `{ id, isOnline: boolean, lastSeen: string | null }[]`.

---

### Task 3 — Typing Indicators Socket Events

**File:** `server/src/sockets/socketManager.ts`

- Implement event handler `typing_start`:
  - Body: `{ conversationId: string, recipientId: string }`
  - Emits `user_typing` `{ conversationId, userId: socket.userId, isTyping: true }` to recipient's personal room (`io.to(recipientId)`).
- Implement event handler `typing_stop`:
  - Body: `{ conversationId: string, recipientId: string }`
  - Emits `user_typing` `{ conversationId, userId: socket.userId, isTyping: false }` to recipient's personal room.

---

### Task 4 — Delivery & Read Status Socket Handlers

**File:** `server/src/sockets/socketManager.ts` & `server/src/controllers/conversationController.ts`

- Implement event handler `mark_delivered`:
  - Body: `{ messageId: string, conversationId: string, senderId: string }`
  - Updates `Message.status = 'DELIVERED'` in database (if current status is `SENT`).
  - Emits `message_status_update` `{ messageId, conversationId, status: 'DELIVERED' }` to sender's personal room (`io.to(senderId)`).
- Update `markAsRead` handler in `conversationController.ts`:
  - When recipient marks conversation as read, update all messages in conversation where `senderId != requestingUserId` and `status != 'READ'` to `status = 'READ'`.
  - Also emit socket event `message_status_update` `{ conversationId, status: 'READ', readerId: requestingUserId }` to the senders.

---

### Task 5 — Integration Tests

**File:** `server/src/tests/presence.test.ts`

Test assertions:
1. Socket connection registers user as online and emits `user_presence` with `isOnline: true`.
2. Socket disconnect updates `lastSeen` in DB and emits `user_presence` with `isOnline: false`.
3. Emitting `typing_start` relays `user_typing` with `isTyping: true` to recipient.
4. Emitting `mark_delivered` updates message status in DB to `DELIVERED` and notifies sender.
5. Marking conversation as read updates messages in DB to `READ` and notifies sender.
